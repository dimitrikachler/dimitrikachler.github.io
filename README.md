# dimitrikachler.github.io

Personal site. Plain HTML and CSS, generated by one Python script with no
dependencies. Pushing to `main` builds and deploys it through GitHub Actions.

## Preview locally

```bash
./serve.sh          # builds, then serves http://localhost:8000
```

Or in two steps:

```bash
python3 build.py
python3 -m http.server 8000 --directory _site
```

`_site/` is generated output and is not committed.

## Where things live

| I want to change... | Edit |
| --- | --- |
| The About page text | `content/about.md` |
| Blog posts | `content/posts/*.md` |
| Publications | `data/publications.json` |
| The news list on the home page | `data/news.json` |
| Drawings | `data/art.json` and `assets/art/` |
| Name, links, nav, photo | `data/site.json` |
| Colours, type, layout | `assets/css/main.css` |
| Page shell (head, sidebar, footer) | `templates/base.html` |

## Writing a post

Create `content/posts/YYYY-MM-DD-slug.md`:

```markdown
---
title: What I learned about influence functions
date: 2026-10-01
summary: One sentence that shows up on the blog index.
tags: [attribution, notes]
accent: mint
draft: false
---

Body text in Markdown.
```

The date in the filename orders the post; the slug after it becomes the URL.
`accent` picks the pastel stripe: `lav`, `mint`, `peach` or `sky`. Set
`draft: true` to keep a post out of the build.

Supported Markdown: headings, bold, italic, strikethrough, inline code, fenced
code blocks, links, images, bullet and numbered lists, block quotes and
horizontal rules. Math renders through KaTeX, `$inline$` and `$$display$$`.

## Adding a publication

Prepend an entry to `data/publications.json`. Publications are grouped by year
automatically, and your own name is highlighted wherever it matches `name` in
`data/site.json`.

```json
{
  "title": "Paper title",
  "authors": ["Dimitri Kachler", "Co Author"],
  "venue": "ACL 2027",
  "status": "accepted",
  "year": 2027,
  "accent": "sky",
  "tags": ["topic"],
  "abstract": "Two or three sentences.",
  "links": [{ "label": "arXiv", "href": "https://arxiv.org/abs/..." }]
}
```

`status` accepts `accepted`, `preprint` or `published`, which controls the
badge next to the venue.

## Adding drawings

Put image files in `assets/art/`, then add entries to `data/art.json`. Any
format a browser can show works. Resize large scans before committing them.

## Still to personalise

- `content/about.md` is scaffolding. Replace it with your own words.
- `data/site.json` has a placeholder Google Scholar URL.
- The profile photo is `assets/img/dim_vatican.jpg`. Two keys in
  `data/site.json` frame the circular crop: `avatar_zoom` is how far to zoom
  in, and `avatar_position` is the point the zoom centres on, given as
  horizontal then vertical percentages. A smaller second number moves the crop
  toward the top of the photo. The build turns those into a background
  position, so no transform is involved and the circle clips cleanly. If the
  configured file is missing the build falls back to the grey placeholder and
  says so.

The stylesheet URL carries a hash of its own contents, so a browser fetches
the new file as soon as the CSS changes. You should never need to hard
refresh.

## Custom domain

Put the hostname in a file named `CNAME` at the repository root. The build
copies it into `_site/` automatically.
